# V2 迁移与验收

## 已落地

主入口 main.py 只挂载 app/api/v2.py；Dashboard 只通过 V2 API 读写。LLM 的五个业务工具复用同一 Store、Jobs 和 PredictionPipeline，不另造一套预测。

| 原问题 | V2 处理 |
|---|---|
| Path/ELO 重复、随机比分反推概率 | 移除生产依赖，使用完整概率模型 |
| 67 截 50、单元素 attention | 全量 68 维普通 MLP；shape 错误直接拒绝 |
| 特征时间泄漏、当前 ELO 回填历史 | 按日重放，生成特征后更新 |
| XGB 双重标准化、全量 scaler | XGB 原始特征；MLP scaler 训练集拟合一次 |
| 强行修改冠军/Top5 | 验证完整概率分布、argmax 与排名一致 |
| 随机签表、错误四强计数 | 固定依赖图、逐轮真实参赛事件 |
| 概率最高队与代表路径混用 | 两字段分别显示 |
| 旧 JSON 覆盖新运行 | 输入内容寻址，结果 append-only |
| 公开计算、无预算 | 写入鉴权、共享计算槽、幂等与取消 |
| 重复模型加载、关机保存模型 | 进程级注册表，仅离线训练写权重 |
| 部署时“修复”结果 | 删除 predeploy 对旧 JSON 的重写 |

## 升级步骤

1. 备份现有数据库、.env 与模型。使用独立分支审阅，升级后 V1 客户端收到 410。
2. 安装 requirements.txt；面板安装 requirements-dashboard.txt。Python 使用 3.12。
3. 配置 DATABASE_URL、ADMIN_API_KEY。已有 PostgreSQL 可保留旧表；启动时只新增已声明的 V2 表。后续表结构变更需要正式迁移，create_all 不会修改现有列。
4. 不加载旧 feature_network/XGBoost 权重，不导入旧 final_agent_result.json。V2 初始没有快照和结果是预期行为。
5. 根据供应商已确认的签表构建 fixtures；使用 canonical team 名称/ID，API 刷新时名称需精确映射。每个来源为 team:<球队> 或 winner:<前序比赛ID>。以两场半决赛加决赛的 demo 生成器作为格式示例。
6. 历史数据要有 match_id/date/home/away/home_score/away_score/neutral/source/score_basis。比分只能是常规 90 分钟；供应商含加时的比分必须先拆分或剔除。原 import_historical_data.py 生成合成数据，禁止改标 verified。
7. 数据审查后导入真实快照，先运行基线。训练与回测使用同一标准化数据；只在审阅样本量、时间切分、模型对比及校准后发布模型包。
8. 运行新测试与历史回归测试。通过 /ready 核对实际模型模式；在面板核对数据截止、来源、完整概率、情景和历史对比。
9. 部署前在目标 Linux/PostgreSQL 环境验收。当前实现没有自动替你部署、触发生产付费 API 或训练真实模型。

## 时间和模型语义

快照固定 as_of；历史特征只读更早日期。finished 场次只能在截止时间之前，scheduled 场次不得已处于过去。API 刷新只更新赛程，保留历史数据及来源；直播或推迟状态拒绝，交管理员复核。

比赛分布为 90 分钟胜平负，平局后双方各 0.5 晋级是透明基线，不能解释为已训练的点球胜率。比分矩阵类别重标后与集成胜平负一致，但类别内比分形状仍依赖 Poisson 假设。

68 维 schema 是版本化工程接口，不是已证明最佳特征。原始 ELO 初值、更新系数、经验进球先验、主场系数仍需真实回测和消融验证。历史发布日期和后续数据修订尚未重建，因此回测不能声称严格模拟当时信息发布过程。

扩展窗口回测中训练集扩展，验证、校准、测试依次前移，测试日期互不重叠。每折重新拟合预处理、模型、权重与温度，不用测试表现回头选参数。平均 Log Loss 为逐折等权；细节和样本数看每折报告。

## 运行限制

- 每个共享数据库同时最多一个预测任务；其他请求 409，不建立无界队列。API-Football 和 LLM 协调各自有一个并发槽。
- 预测 100–20,000 次，工作流时间预算默认 120 秒，最大 600 秒；取消在模拟循环检查，结果落库前再次原子检查。
- LLM 每次最多 6 个步骤，每次请求最长 30 秒，步间检查 150 秒预算；正在执行的业务工具受自身预算约束，因此不是严格 150 秒总截止。
- API-Football 每日额度以 UTC 日期共享计数，失败调用也计入；其他应用使用同一供应商密钥的额度不在本库内。
- 后台进程崩溃后租约 12 分钟到期，下一次提交回收；不自动恢复半成品。长期任务可用专门 worker/队列进一步扩展。
- 当前同步 LLM HTTP 调用没有自动重试，避免重复触发昂贵工作流。自然语言可能幻觉，权威结果单独返回。
- 数据库、模型包和外部 API 均需要目标环境验证。本地测试中 provider/LLM 使用替身，不消耗用户配额。
